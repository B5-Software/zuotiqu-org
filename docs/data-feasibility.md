# 录取数据采集可行性（M0 spike，部分完成）

日期：2026-10-31 之后的检查。这一步只检查了 robots 规则，**没有做真实采集**。

## 已检查

| 站点 | robots.txt | 结论 |
|---|---|---|
| gaokao.chsi.com.cn（阳光高考） | 允许抓取，仅禁止 `/zzbm/tjr/` | 可以考虑采集，但需要人工核对使用条款（条款未检查） |
| www.neea.edu.cn（国家教育考试院） | 返回 404，无 robots 规则 | 无法从 robots 判断，需要人工确认 |

## 未检查

- 阳光高考的使用条款。计划要求采集前核对，这一步没有做。
- 各省教育考试院。计划里要求挑 3 个数据最规整的省份做试点，这一步没有做，因为需要逐个打开官方页面检查数据格式。

## 数据格式差异（推测，未验证）

- 一分一段表、投档线往往以 PDF、图片或不规则表格发布，需要解析。计划里的思路是先 PDF 文本提取，OCR 作为后备，解析结果必须人工抽检。
- 老高考（文理）、新高考 3+3、新高考 3+1+2 的数据结构不同，模型里已通过 `examType` 和 `track` 区分。

## 结论

- 管线与模型已就绪，页面可以接入真实数据，只需要把符合 schema 的 JSON 放进 `public/data/gaokao/<省>/<年>.json`，`npm test` 会校验。
- 真实采集前需要完成：阳光高考使用条款核对、至少 3 个省份的数据格式确认。
